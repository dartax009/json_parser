# JSON PARSER

Библиотека для проверки JSON-строки и её обработки.

Для сборки и работы в ОС Linux требуются следующие заголовочные файлы:
- stdlib.h
- string.h
- stdint.h
- sys/mman.h
- sys/stat.h
- fcntl.h
- unistd.h
- stdio.h (если необходим вывод информации об ошибках на экран; по умолчанию не используется)

Для других операционных систем (не Linux) требуются:
- stdlib.h
- string.h
- stdint.h
- stdio.h (если необходим вывод информации об ошибках на экран; по умолчанию не используется)

Чтобы включить вывод сообщений об ошибках, определите макрос `PRINT_ERROR_INFO` перед подключением библиотеки:
```c
#define PRINT_ERROR_INFO
#include "json_parser.h"
```

Библиотека использует динамическую память (malloc).

## Что может?

- Проверять JSON-строку на соответствие структуре (без проверки обязательности наличия указанных полей).
- Проверять JSON-строку на соответствие структуре с контролем количества вхождений указанных полей.
- Предоставлять возможность обрабатывать поля JSON-строки (вызов пользовательских функций в процессе разбора).

## Что не может?

- Проверять все возможные комбинации JSON-строк (утверждение требует дополнительного тестирования).
- Гарантировать стабильную работу во всех сценариях (необходимо больше тестов).

## Интерфейс взаимодействия с библиотекой
### Библиотека предоставляет следующие функции:

|№|Название|Прототип|Аргументы|Возвращаемые значения|
|-|-|-|-|-|
|1|Разобрать json в соответствии с json_map_t|uint8_t parsing_json (const file_inf_t *const file_inf, json_map_t *const json_map, const uint8_t check_required)|file_inf_t *file_inf – информация о строке, её размере и файле (если он был открыт с помощью init_json_mmap). <br> json_map_t *json_map – структура ожидаемого JSON. <br> uint8_t check_required – использовать ли проверку количества вхождений (0 – нет, 1 – да).| [0] - успешное завершение. <br> [>0] - ошибка. Библиотека возвращает 1 при любой внутренней ошибке; другие значения могут быть возвращены пользовательскими обработчиками.|
|2|Открыть файл json и спроецировать его в ОЗУ для дальнейшей работы|uint8_t init_json_mmap (const char * const path, file_inf_t *file_inf)|char *path - путь к файлу. <br> file_inf_t *file_inf - структура для хранения информации об открытом файле.|[0] - успех. <br>[1] - не удалось открыть файл. <br> [2] - не удалось получить информацию о размере файла. <br> [3] - не удалось спроецировать файл в ОЗУ.|
|3|Закрыть файл json и удалить его проекцию в ОЗУ|uint8_t deinit_json_mmap (file_inf_t *file_inf)|file_inf_t *file_inf - информация о ранее открытом файле|[0] - успех. <br>[1] - не удалось удалить проекцию файла из ОЗУ. <br>[2] - не удалось закрыть файл.|

### Прототип функции-обработчика поля:
```c
typedef uint8_t (*handler_json)(const char * const field_value, const size_t size);
```
- field_value [in] указатель на начало значения поля, данные которого необходимо обработать.
- size  [in] размер данных (длина строки значения).

Возвращаемое значение:
- [0] - успешное завершение.
- [>0] - пользовательский код ошибки.
 
Функции-обработчики предназначены для выполнения действий в процессе разбора JSON. Например, если в JSON есть поле "name", и вы хотите сохранить его значение в своей структуре, вы создаёте функцию-обработчик, которая выполняет нужные операции (возможно, с дополнительными проверками). Подробности и примеры приведены ниже в разделе "Работа библиотеки".

### Структура file_inf_t

|№|Название|Назначение|
|-|-|-|
|1|fd|Дескриптор файла (используется init_json_mmap). Если строка уже находится в ОЗУ, поле может быть любым.|
|2|file_len|Длина JSON-строки. При использовании init_json_mmap содержит размер файла.|
|3|file|Указатель на начало JSON-строки. При использовании init_json_mmap хранит начало разделяемой памяти, созданной с помощью mmap.|

### Структура json_map_t
|№|Название|Назначение|
|-|-|-|
|1|field_name|Ожидаемое имя поля. Для элементов массива без имени указывается NULL.|
|2|func|Функция-обработчик (handler_json). Может быть NULL, если обработка не требуется.|
|3|field_type|Тип поля в соответствии с [jsmn.h](https://github.com/zserge/jsmn "Ссылка на git hub разработчика")|
|4|json_map|Указатель на вложенную структуру json_map_t (для объектов или массивов).|
|5|min_count|Обязательное минимальное количество вхождений поля (0 – поле может отсутствовать).|
|6|count|Счётчик фактических вхождений. Должен быть инициализирован нулём.|

Примечание: Поле json_map является указателем на другую карту. Это позволяет строить иерархические структуры: если текущее поле имеет тип JSMN_OBJECT или JSMN_ARRAY, то json_map указывает на карту, описывающую содержимое этого объекта или массива.

Значения field_type (из [jsmn.h](https://github.com/zserge/jsmn "Ссылка на git hub разработчика")):
```c
typedef enum {
	JSMN_UNDEFINED = 0,
	JSMN_OBJECT = 1 << 0,
	JSMN_ARRAY = 1 << 1,
	JSMN_STRING = 1 << 2,
	JSMN_PRIMITIVE = 1 << 3
} jsmntype_t;
```
- JSMN_UNDEFINED - неизвестный тип; в библиотеке используется как стоп-сигнал
- JSMN_OBJECT - объект. Все что окружено в "{...}"
- JSMN_ARRAY - массив. Все что окружено в "[...]"
- JSMN_STRING - строка. Все что окружено в ""
- JSMN_PRIMITIVE - примитив (true, false, null или число без кавычек).

Важно: Последним элементом любой карты всегда должен быть макрос END_MAP_JSON.

## Работа библиотеки

Данная библиотека основана на [jsmn.h](https://github.com/zserge/jsmn "Ссылка на git hub разработчика") и использует его подход к разбору JSON. В текущей реализации jsmn уже включена в состав библиотеки (определённая версия, совместимая с данным парсером).

```json
{
    "name" : "Jack",
    "age" : 27
}
```
Карта для него будет выглядеть так:
```c
static const json_map_t any_name[] =
{
    {"name", any_handler1, JSMN_STRING, NULL},
    {"age", any_handler2, JSMN_PRIMITIVE, NULL},

    END_MAP_JSON
};
```
Корневой объект ({}) подразумевается и не указывается в карте. Порядок полей не важен (библиотека пока не контролирует его). Обработчики могут быть NULL, если не требуется никаких действий.

Усложним пример – значение поля name само является объектом:
```json
{
    "name":{
        "first": "Jack",
        "last": "Hugecock"
    },
    "age" : 27
}
```
Карта:
```c
static const json_map_t name_map[] =
{
    {"first", any_handler, JSMN_STRING, NULL},
    {"last", any_handler, JSMN_STRING, NULL},

    END_MAP_JSON
};

static const json_map_t person_map[] =
{
    {"name", NULL, JSMN_OBJECT, name_map},
    {"age", any_handler2, JSMN_PRIMITIVE, NULL},

    END_MAP_JSON
};
```
Поле name имеет тип JSMN_OBJECT, поэтому мы связываем его с отдельной картой name_map.

Добавим массив hobbies:
```json
{
    "name":{
        "first": "Jack",
        "last": "Hugecock"
    },
    "age" : 27,
    "hobbies": [
        "Reading",
        "Walking a cock"
    ]
}
```
Карта:
```c
static const json_map_t hobbies_map[] =
{
    {NULL, any_handler, JSMN_STRING, NULL},

    END_MAP_JSON
};
static const json_map_t name_map[] =
{
    {"first", any_handler, JSMN_STRING, NULL},
    {"last", any_handler, JSMN_STRING, NULL},

    END_MAP_JSON
};

static const json_map_t person_map[] =
{
    {"name", NULL, JSMN_OBJECT, name_map},
    {"age", any_handler, JSMN_PRIMITIVE, NULL},
    {"hobbies", NULL, JSMN_ARRAY, hobbies_map},

    END_MAP_JSON
};
```
Элементы массива hobbies не имеют имён, поэтому в карте hobbies_map указано NULL в поле field_name. Библиотека будет ориентироваться только на тип (JSMN_STRING). Если требуется различать элементы, это нужно делать внутри обработчика.

Ещё пример – массив объектов:
```json
{
    "name":{
        "first": "Jack",
        "last": "Hugecock"
    },
    "age" : 27,
    "phoneNumbers": [
        {
            "type": "mobile",
            "number": "+7-123-456-7890"
        },
        {
            "type": "home",
            "number": "+7-987-654-3210"
        }
    ],
}
```
Карта:
```c
static const json_map_t phoneNumbers_obj[] =
{
    {"type", any_handler, JSMN_STRING, NULL},
    {"number", any_handler, JSMN_STRING, NULL},

    END_MAP_JSON
};

static const json_map_t phoneNumbers_map[] =
{
    {NULL, NULL, JSMN_OBJECT, phoneNumbers_obj},

    END_MAP_JSON
};
static const json_map_t name_map[] =
{
    {"first", any_handler, JSMN_STRING, NULL},
    {"last", any_handler, JSMN_STRING, NULL},

    END_MAP_JSON
};

static const json_map_t person_map[] =
{
    {"name", NULL, JSMN_OBJECT, name_map},
    {"age", any_handler, JSMN_PRIMITIVE, NULL},
    {"phoneNumbers", NULL, JSMN_ARRAY, phoneNumbers_map},

    END_MAP_JSON
};
```
Здесь phoneNumbers – массив объектов без имён. В карте phoneNumbers_map указано JSMN_OBJECT с переходом на карту объекта.

### Динамические массивы и объекты

Если нужно узнать количество элементов в массиве или объекте (например, для динамических данных):

```json
{
    "any_array": [
        "any1",
        "any2",
        "any3"
    ],
    "any_object":{
        "any1":1,
        "any2":2,
        "any3":3
    }
}
```

Карта:

```c
static const json_map_t any_array_map[] =
{
    {NULL, NULL, JSMN_STRING, NULL},

    END_MAP_JSON
};

static const json_map_t any_object_map[] =
{
    {"any1", NULL, JSMN_PRIMITIVE, NULL},
    {"any2", NULL, JSMN_PRIMITIVE, NULL},
    {"any3", NULL, JSMN_PRIMITIVE, NULL},

    END_MAP_JSON
};

static const json_map_t any_map[] =
{
    {"any_array", any_handler_array, JSMN_ARRAY, any_array_map},
    {"any_object", any_object_handler, JSMN_OBJECT, any_object_map},

    END_MAP_JSON
};
```

В этом случае аргумент size у обработчиков any_handler_array и any_object_handler будет равен количеству элементов (здесь – 3).

### Обязательные поля

Иногда требуется, чтобы некоторые поля присутствовали обязательно. Например:

```json
{
    "name":{
        "first": "Jack",
        "last": "Hugecock"
    }
}
```

Если мы хотим, чтобы объект name и поле first встретились хотя бы один раз, карта будет такой:

```c
static const json_map_t name_map[] =
{
    {"first", any_handler, JSMN_STRING, NULL, 1},
    {"last", any_handler, JSMN_STRING, NULL},

    END_MAP_JSON
};

static const json_map_t person_map[] =
{
    {"name", NULL, JSMN_OBJECT, name_map, 1},

    END_MAP_JSON
};
```

Пятое поле (min_count) задаёт минимальное количество вхождений. При вызове parsing_json с третьим аргументом 1 библиотека проверит, что фактическое число вхождений (count) не меньше min_count для каждого поля. Это замедляет разбор, так как требуется обход всех полей и сброс count. На данный момент такая проверка не работает для динамически повторяющихся вложенных полей (например, если объект name встречается много раз и требуется, чтобы поле first было в каждом из них).

## Замечания

По результатам тестирования, вложенности любой сложности обрабатываются корректно, если карта составлена верно. Примеры кода и тестовые JSON-файлы можно найти в директории example/.

Чтобы выполнить только проверку структуры без вызова обработчиков, укажите во всех полях func = NULL.

## Как использовать
- Составить ожидаемую карту
- Написать необходимые функции-обработчики
- Если JSON читается из файла:
```c
file_inf_t fl_inf = {0};    // Создаем структуру для хранения json
init_json_mmap("any/path/to/json", &fl_inf); // Открываем файл и вытягиваем его в ОЗУ

parsing_json(&fl_inf, my_map, 0);   // Анализируем и обрабатываем json. Третий аргумент может быть 0 или 1 в зависимости от необходимости проверять кол-во вхождений полей в json

deinit_json_mmap(&fl_inf); // Освобождаем ресурсы
```
- Если JSON уже находится в памяти:
```c
file_inf_t fl_inf = {0};    // Создаем структуру для хранения json

fl_inf.file = ptr_to_json;      // Ставим указатель
fl_inf.file_len = size_json;    // Указываем размер строки

parsing_json(&fl_inf, my_map, 0);   // Анализируем и обрабатываем json. Третий аргумент может быть 0 или 1 в зависимости от необходимости проверять кол-во вхождений полей в json
```

## Известные ограничения и планы по развитию

- Порядок полей: библиотека не контролирует порядок следования полей в JSON. Если для вашей задачи важен порядок, это придётся проверять дополнительно.
- Проверка обязательных полей в динамических структурах: в текущей версии нельзя гарантировать, что поле first обязательно в каждом объекте массива (например, в массиве объектов phoneNumbers). Проверка min_count работает только на верхнем уровне или для статически известного количества вхождений.
- Производительность: при включённой проверке обязательных полей (check_required = 1) выполняется дополнительный проход по карте для сброса счётчиков, что может замедлить разбор больших JSON-файлов.
- Тестирование: библиотека требует более обширного тестирования на разнообразных JSON-структурах.
- Поддержка сложных сценариев: в будущем планируется улучшить механизм обязательных полей, добавить возможность контроля порядка и, возможно, оптимизировать внутренние алгоритмы.
